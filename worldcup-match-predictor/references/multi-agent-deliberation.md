# Monte 多智能体研判协议

本协议用于 1/4 决赛及之后的单场或少量世界杯预测。目标不是用多数票制造确定感，而是让不同模型先独立判断、再相互质疑，最终得到可审计的概率共识。

## 核心原则

1. **事实不投票，观点才聚合**：名单、伤停、停赛、实际首发等事实由证据裁决，不得用“多数 agent 都这么说”确认。
2. **先盲审，后讨论**：首轮 agent 看不到其他观点、用户比分倾向、已有预测比分和竞彩赔率。
3. **用户观点是待检验假设**：单独保存为 `user_hypothesis`，首轮结束后才由红队和裁决官检验，不直接进入概率。
4. **不强迫一致**：最终必须给出一个共识结论，但有证据的少数意见必须保留。
5. **结果与机制分开评分**：比分命中但阵容事实或比赛机制判断错误，记为“结果命中、机制失配”。
6. **只保存可审计摘要**：保存结构化结论、证据引用、质疑与修订，不保存隐藏思维过程或冗长原始对话；同时必须生成面向用户的逐角色审计附录，不能只显示共识结果。

## 角色

### 无票控制角色

- `FACT` 事实核验官：冻结名单、伤停、停赛、预计首发、裁判和信息截止时间；拥有硬事实否决权。
- `RED` 红队：寻找共同盲区、名将偏见、用户锚定、早球/红牌/点球/大比分尾部脚本；不参与均值。
- `AGG` 裁决官：只基于证据账、锁定观点和质疑记录给出最终结论，不得新增事实。
- `MKT` 市场审计：在足球共识锁定后才揭示竞彩赔率；市场分歧只能触发事实复查，不能静默改写概率。

### 有票预测角色

- `QBASE` 概率基线：近期比赛、攻防产出、对手强度、基础率和预期进球。
- `MONTE` 情景模拟：正常、早球、落后追分、红牌/点球等情景权重及比分矩阵。
- `TACT` 战术对位：阵型、压迫、转换、定位球、关键通道和逐时段进程。
- `SQUAD` 阵容与教练：可用球员、首发分支、替补后手、体能、主教练临场调整。
- 淘汰赛可追加 `TOUR`：常规时间保守度、加时、点球与晋级条件概率。

默认一名 agent 负责一个角色并批量分析当天所有比赛，不要为每场重复创建整套角色。若子 agent 不可用，主 agent 需按同样顺序完成相互隔离的角色化复核，并在报告中注明“顺序回退，非真正独立盲审”。

## 执行轮次

### R0 证据冻结

1. 先完成 roster 台账与双源核验。
2. 创建 `snapshot_id`，建议为 `YYYYMMDD-HHMM-BJ`。
3. 每条关键事实记录 `fact_id`、结论、来源 URL、发布时间、核验时间、状态 `verified/conflict/missing`。
4. 把用户倾向保存为 `user_hypothesis`，不要传给有票角色。
5. 不向有票角色提供竞彩赔率或上一版预测比分。

### R1 独立盲审

使用 fresh subagent context；只传比赛、事实快照、历史赛果和统一输出契约。每个有票角色独立提交：

- 90 分钟胜/平/负概率。
- 完整比分矩阵，或 `0-0` 至 `5-5` 加 `home_other/draw_other/away_other`。
- 主脚本、反脚本、尾部脚本。
- 关键驱动、假设、反证条件和数据质量。
- 一句 `lean`，例如“主胜，首选 1-0，次选 2-0”。
- 一份 `audit_summary`：用简洁、可公开的文字写明初判、2–4 条关键依据和本角色最担心的反证；不得输出逐字隐藏思维链。

提交后锁定，不向任何角色展示平均值或多数方向。

### R2 机械校验

1. `p90` 三项合计必须为 1。
2. 比分矩阵合计必须为 1，并能反推出相同的 `p90`；误差超过 0.5 个百分点退回重算。
3. 检查每个球员是否存在于当天 roster 快照且可用。
4. 检查事实引用和信息截止时间；来源冲突不得写成确定事实。

### R3 匿名交叉质疑

把首轮观点匿名为 A/B/C/D。每名原 agent 至少质疑：

- 一个与自己概率距离最大的观点；
- 一个具体比赛机制，而不是只说“我不同意比分”。

质疑需包含 `target_claim`、`counter_hypothesis`、`evidence_gap`、预计影响的百分点和希望补查的事实。

### R4 事实裁决与修订

`FACT` 只裁决事实冲突；随后把匿名质疑发送回原 agent。每名有票 agent 都必须提交 `final` 和 `revision_reason`。若保持原判断，使用 `{"unchanged": true, "revision_reason": "..."}` 明确确认，不得由聚合器静默回退到首轮。不得奖励向多数靠拢。

### R5 红队与共识

1. `RED` 检查群体是否共同忽视弱队进球、大比分、裁判、门将、补水调整、替补和用户锚定。
2. 若红队发现硬事实错误，建立新快照并重跑；若只是合理反方，写入少数报告。
3. 运行 `scripts/monte_consensus.py` 做线性概率池和分歧度量。
4. `AGG` 读取数字共识、证据账、质疑和少数报告，给出最终比分、概率、比赛进程与置信度。
5. 根据四个 voting agent 的锁定输出、质疑和修订记录组装 `audit_display`；每名角色都必须有 `initial_view/basis/challenge/revision`，并追加交叉质询、红队和裁决摘要。

### R6 市场揭盲

足球结论锁定后再抓取竞彩。比较市场与共识；重大差异只能触发一次事实复查。没有新事实时，不得为了贴盘改写概率。

## 聚合规则

- 冷启动阶段所有有票角色等权。
- 至少积累 30 场可结算预测后，才允许根据滚动 log-loss 做收缩后的历史加权。
- 历史加权时单个角色权重不得超过 35%，避免一个角色重新形成一言堂。
- 使用线性概率池：`P(k) = sum(weight_i * P_i(k))`，保留少数概率质量。
- 同时输出：
  - `jsd_wdl`：胜平负观点的 Jensen-Shannon 分歧。
  - `max_spread_pp`：任一赛果的最大概率极差。
  - `modal_dissent_weight`：不支持共识首选赛果的权重。
  - `predictive_entropy`：比赛本身的不确定性；不要与专家分歧混淆。
- 高分歧仍需发布数值共识，但不得标为“稳胆”，并列展示至少两个比赛脚本。

## 硬闸门

- `not_in_squad/replaced_out/ruled_out/suspended` 球员出现在首发、后手或点球手中：阻止出卡。
- 无来源、无时间戳或来源冲突：不得用确定语气。
- 用户观点或球星名气是唯一依据：删除该论据。
- 关键球员状态未决：不得给高置信度，必须给有/无该球员的分支。
- 裁决官新增证据账之外的事实：退回重审。
- 高分歧共识：不得标“稳胆”。
- 生产运行必须使用 `monte_consensus.py --require-panel`；缺少 schema v2、面板或最终修订时阻止出卡。默认非严格模式只用于兼容历史旧 JSON。
- 严格模式缺少 `audit_display.enabled=true`、任一 voting agent 的初判/依据/质疑/修订，或缺少交叉质询、RED、裁决摘要：阻止出卡。
- 审计卡若只重复最终比分、没有展示观点变化与争论焦点：视为不合格产物。

## 赛后评分

每场预注册最多 5 条可观察机制。赛后分别计算结果方向、Brier/log-loss、比分误差、事实准确率和机制命中率。结果命中但关键事实错误或机制命中少于 3/5，标记“结果命中、机制失配”，不得因此提高该角色权重。
