# 世界杯赛事比分预测（World Cup Match Predictor）

为指定日期的世界杯比赛生成**比分预测**与**投注参考**。流程分七步：赛后复盘校准 → 阵容台账更新 → 确定赛程 → 多维信息收集 → 多智能体盲审与质疑 → 共识建模 → 输出预测报告（含赔率对比与下注建议）。

> ⚠️ 投注建议仅针对世界杯比赛，且仅供参考。理性娱乐，所有预测均存在不确定性，不构成任何盈利保证。

---

## 触发与输入

- **默认行为**：预测「北京时间明天」的所有世界杯比赛。
- **可指定日期**：用户给出具体日期（如"6月20日"、"后天"）则预测当日比赛。
- **可指定单场**：用户只问某两队对阵，则只分析该场。
- **定时调用**：每天下午由定时任务触发时，等同"预测明天所有比赛"。

开始前，用 `get_current_time`（builtin MCP）确认"今天/明天"对应的真实日期，避免日期算错。

## 第零步：赛后复盘与模型校准（必须先做）

每次生成新报告前，先复盘本技能近期已经生成过的预测报告，尤其是 `reports/worldcup_*_predictions.json` 中目标日期早于当前日期的比赛。

1. 读取历史报告里的每场预测：
   - 首选比分、次选比分、胜平负概率、总进球预测、让球/总进球/波胆建议。
2. 联网核对真实赛果与关键比赛过程：
   - 最终比分、半场比分、红牌/点球/早球、关键伤退、轮换、场地显著影响。
   - 必须抓取每场比赛的**实际首发阵容**与**实际替补上场名单**：双方首发 11 人、阵型（若来源提供）、每次换人时间、换上/换下对象、伤退说明。
   - 新报告的 `00` 号复盘卡必须逐场单独列出“实际首发”和“替补上场”；若可靠来源暂时无法查全，必须写“首发/换人信息不足”并注明缺口，不能直接省略。
   - 复盘时要检查昨日预测提到的关键球员是否实际首发、替补、未出场、伤退或停赛；若预测依赖了未出场球员，必须在误差归因里明确指出。
   - 未登场替补不得写成实际参与比赛或改变比赛的后手；高知名度球员若整场未上（unused substitute），要把“为何未使用”本身作为体能、跑动能力、战术选择或风险管理信号来复盘。
   - 若无法查到完整过程，至少核对最终比分，并明确过程信息不足。
3. 做结构化误差归因：
   - **方向误差**：胜平负是否判断错。
   - **比分误差**：首选/次选是否命中，净胜球差和总进球差偏大还是偏小。
   - **赔率误差**：让球盘、总进球最低档、波胆市场是否比自己判断更接近真实结果。
   - **思维误差**：是否套用了固定模板（例如"强队打弱队=3-0"、"均势队=1-0/1-1"），是否低估大比分、冷门、早球导致的开放节奏、末轮/第二轮净胜球动机。
4. 把复盘结论写进新报告的汇总部分，作为"今日校准"：
   - 明确本次会提高或降低哪些因素权重（如早球后比赛开放、深让盘被打穿概率、弱队反击进球概率）。
   - 如果连续预测出现同类比分模板，必须主动打破模板，给出更宽的比分分布。
5. 复盘只用于校准，不要为了"显得不一样"而故意逆市场或制造冷门；所有调整仍需回到真实信息与赔率结构。

## 第零点五步：阵容台账与可用性更新（必须在分析前做）

每次生成新报告前，必须先建立或更新目标日期的 roster 台账，避免凭印象写入未入选、伤退、停赛或已经被替换的球员。

1. 运行或更新 `worldcup-match-predictor/scripts/update_rosters.py`：
   - 输出目录：`data/rosters/YYYY-MM-DD/`。
   - `all_rosters.csv`：全量球队名单台账。
   - `teams/<TEAM_CODE>.csv`：单队名单台账，例如 `teams/ENG.csv`、`teams/USA.csv`。
   - `availability_overrides.csv`：当天新闻、官方赛前稿、伤停、停赛、补招和名单冲突的覆盖表。
2. CSV 必须包含这些字段：`team`、`team_code`、`player`、`position_group`、`club`、`roster_status`、`availability_status`、`absence_note`、`expected_absence_matches`、`suspension_status`、`yellow_card_risk`、`starting_role`、`source_url`、`last_checked_bj`。
3. 基础名单优先使用 FIFA/足协官方名单；如果官方页面为动态内容无法稳定解析，可使用明确写明“最终 26 人名单已提交 FIFA/官方公布”的主流名单源作为 base roster，并在 `base_roster_source` 标注。
4. 每天必须用最新官方赛前稿、球队发布会、主流媒体 team news 更新 `availability_overrides.csv`：
   - 伤缺、伤疑、预计缺席几场、能否赶上下一轮。
   - 红牌停赛、累计黄牌停赛、黄牌再吃一张的风险。
   - 赛前补招/替换，例如 `Senesi（ARG）替换 Balerdi（ARG）`。
   - 名单冲突，例如不同来源对某球员是否仍在 squad 中说法不一致时，标为 `source_conflict`，不得写成确定可用。
5. 生成每场预测前，先读取双方 `teams/<TEAM_CODE>.csv`：
   - `not_in_squad`、`replaced_out`、`ruled_out`、`injured`、`suspended` 的球员不得出现在首发、替补后手、点球手或战术关键点中。
   - `fitness_doubt`、`available_fitness_managed`、`source_conflict` 只能写成不确定变量，不得写成确定主力。
   - 若球员在最终名单里但最近几场不是主力路径，只能写成轮换/后手，不能凭名气写成核心。
6. 报告 JSON 的 `summary` 或 `reflection` 需注明 roster snapshot 日期；如果当天卡片修正了名单幻觉，要在 00 号卡明确写出来。

## 第一步：确定赛程

1. 用 `web_search` 搜索目标日期的世界杯赛程，关键词示例：`世界杯 {日期} 赛程 对阵`、`World Cup fixtures {date}`。
2. 对每场比赛提取：
   - 对阵双方、所属小组
   - **开球时间（北京时间 + 当地时间）** —— 当地时间用于评估时差、恢复与球员适应
   - 比赛城市与球场
3. 列出当天全部比赛，逐场进入后续分析。

## 第二步：多维信息收集（每场比赛都要做）

这是预测质量的核心。**必须实际联网收集**，不能凭空臆测。对阵双方各自收集以下维度，建议并行发起多次 `web_search`，再对关键结论用 `web_fetch` 核实。

### A. 近期状态（近半年所有国际赛事）
- 搜集两队近半年**全部国际赛事**成绩（世界杯、预选赛、热身赛、洲际赛事、欧国联等）。
- 关注：胜负走势、进失球数、连胜/连败、对强队/弱队的不同表现。
- 判断"势头"：是上升期还是低迷期。

### B. 本届世界杯进程与状态
- 该队本届已踢的比赛结果与表现（控球、射门、防守漏洞）。
- 体能消耗、是否经历加时、连续作战间隔天数。

### C. 历史交锋战绩（H2H）
- 两队过往交锋记录，尤其近 5–10 次。
- 大赛中的交锋（世界杯/洲际杯往往比热身赛更有参考价值）。

### D. 打法风格与战术克制
- 双方阵型与风格（控球型 / 防反型 / 高位逼抢 / 定位球强队等）。
- 风格相性：谁的打法克制谁，中场与边路对位。

### E. 球员状态与阵容
- 核心球员状态、近期是否有伤、关键射手/中场是否健康。
- 门将状态、后防稳定性。
- 必须交叉核对至少两个赛前阵容/伤停来源（如 FIFA Match Centre、ESPN/Sports Illustrated/Opta Analyst/主流媒体预测首发、球队发布会或足协消息）。
- 预测首发、替补后手和点球手不得凭记忆填写；如果媒体明确说明某球员伤缺、未入名单、已伤退或本届后续不可用，报告中必须写清，并不得把该球员列为可用后手。
- 对 Kubo（JPN）、Mitoma（JPN）这类高知名度球员尤其要做二次核查，避免因为名气或历史印象把不可用球员写进当前阵容。

### F. 停赛与黄牌风险（关键且易被忽略）
- **本场确定停赛**的球员（红牌或累计黄牌已达停赛）。
- **黄牌累计风险**：小组赛阶段有球员处于"再吃 1 黄即停赛"，可能影响其拼抢强度与表现。
- 伤病停赛、临时退队情况。

### G. 小组出线形势（小组赛阶段尤为重要）
- 当前小组积分榜（同组其他队可能已先踢）。
- 各队出线需求：是必须赢、可以保平、还是已出线可能轮换。
- "默契球"风险：末轮双方都满意某比分时，可能踢得保守。

### H. 场地与外部因素（不再常规输出天气）
- 主客场 / 中立场，当地球迷氛围与到场支持。
- 草皮、场地尺寸、人工/天然草、封闭球场或开放球场对传控、长传、定位球和体能的影响。
- 不再把普通天气作为预测卡片的独立区块，也不要输出 `weather` 字段。
- 只有极端天气、顶棚关闭/开启、草皮异常、长途旅行或高原/封闭场馆等确实影响比赛进程的因素，才可压缩写入 `other_factors`，不得单独生成“天气/场地”区块。

### I. 主裁判与出牌尺度（淘汰赛尤为关键）
- 查询本场主裁判与 VAR/第四官员（若官方尚未公布，必须标注“未公布，按可能人选/赛事平均尺度估计”，不得臆造姓名）。
- 收集主裁判过去国际赛事、洲际赛事或本届世界杯的执法数据：
  - 场均黄牌、红牌、点球、犯规尺度、是否常早牌控场。
  - 是否偏向保护比赛流畅，还是更愿意用牌压制身体对抗。
  - 典型例子可用作校准，例如马宁这类整体出牌较多的裁判。
- 结合两队打法、逼抢强度、边路一对一、防守转换犯规、淘汰赛压力，给出：
  - **预计总黄牌数区间**（如 3-5 张 / 5-7 张）
  - 红牌或点球尾部风险
  - 哪一队更可能吃牌，以及原因

### J. 主教练、临场调整与 26 人后手
- 分析双方主教练的战术偏好、保守/激进程度、临场换人质量、淘汰赛经验和短板。
- 本届世界杯存在上下半场中段补水时间：只要死球满足条件，球队会到场边补水。补水时间等同于一次短暂停，主教练可快速调整站位、压迫触发点、传中方向和换人准备；淘汰赛中必须提高主教练临场调整权重。
- 复盘时要重点检查补水时间、半场、加时中场和换人窗口后的战术变化；例如强队落后后是否通过传中方式、边路结构或替补前锋完成逆转。
- 不只看首发 11 人，要把 26 人名单视为一整个 team：
  - 替补席是否有改变节奏的边锋、中锋、定位球手、后腰、防守型换人。
  - 领先后能否守住，落后后是否有 Plan B。
  - 主教练是否存在固执、慢换人、不会保护领先、过度轮换等已知风险。
- 对类似 Bielsa、Roberto Martínez 这类风格鲜明或临场争议较多的教练，要把“风格在世界杯淘汰赛能否兑现”单独作为变量，而不是只看纸面阵容。

### K. 淘汰赛状态与加时/点球
- 淘汰赛阶段必须同时输出两层判断：
  - **常规时间预测**：90 分钟比分、胜平负概率、总进球倾向。
  - **全场/晋级预测**：若常规时间打平，推测加时赛是否进球、是否进入点球大战、最终晋级队。
- 评估加时赛和点球大战概率：
  - 双方常规时间保守程度、替补深度、体能消耗、门将扑点能力、点球手储备。
  - 教练是否会在 70 分钟后主动求稳，还是换攻击手争取 90 分钟解决。
  - 若预测进入点球大战，要给出点球大战胜率倾向和依据。
- 若用户询问正在进行中的 live 比赛或点球大战，必须以用户给出的当前阵容图/换人信息和最新 live 数据为准；已被换下、被罚下或伤退的球员不得列入可能点球手或后续战术后手。
- live 判断中若无法确认某球员是否仍在场，必须明确“不确定”，不要把他写进确定名单。

### L. 人名所属队伍标注（必须）
- 报告中提到球员、主教练、助理教练、主裁判等具体人名时，必须在人名后加三字母国家/队伍简称，方便读者区分身份归属。
- 球员、主教练、助教默认标注其**本场所属球队**，例如 `Davies（CAN）`、`Hugo Broos（RSA）`、`Marsch（CAN）`。
- 主裁判、VAR、第四官员默认标注其**国籍**，例如 `João Pinheiro（POR）`、`马宁（CHN）`。
- 若主教练国籍和执教队伍不同，且该差异对分析有意义，可写成 `Roberto Martínez（POR 主帅/ESP）`；但普通比赛分析中至少要保留执教队伍简称。
- 一张卡片内第一次出现人名时必须标注；若同一段同时提到双方多名球员/教练，重复出现也要尽量标注，避免用户需要凭记忆判断归属。
- 在 `key_factors`、`coach_tactics`、`bench_depth`、`referee`、`card_prediction`、复盘卡正文和投注建议中都适用本规则。

> 收集时优先权威来源（FIFA、各国足协、主流体育媒体、专业数据站）。把每队的关键结论汇总成简短要点，供建模使用。

## 第三步：Monte 多智能体交叉研判与比分建模

1/4 决赛及之后，或目标日期只有 1–2 场比赛时，默认执行 `references/multi-agent-deliberation.md`。核心要求：

1. 建立带 `snapshot_id` 的事实快照；名单、伤停、停赛等事实由 `FACT` 核验，不参与投票。
2. 把用户给出的比分或赛果倾向单独登记为 `user_hypothesis`，不得传给第一轮预测角色。
3. 使用 fresh subagent context 并行启动 `QBASE`（概率基线）、`MONTE`（情景模拟）、`TACT`（战术对位）和 `SQUAD`（阵容/教练）角色；淘汰赛可增加 `TOUR`。同一角色可以批量分析当天所有比赛。
4. 首轮 agent 看不到其他观点、当前竞彩赔率、已有预测比分和用户倾向；必须先锁定 `p90`、比分矩阵、比赛脚本、反证条件和一句 `lean`。
5. 机械检查概率和、比分矩阵与胜平负一致性、球员可用性和来源引用；不合格输出退回原角色重算。
6. 匿名交换观点并进行一轮交叉质疑；事实争议由 `FACT` 裁决，各角色再提交一次最终版本，允许保持原判断。
7. 使用不投票的 `RED` 寻找共同盲区和尾部脚本；使用不投票的 `AGG` 汇总，不得用多数意见裁决事实。
8. 运行 `scripts/monte_consensus.py <report.json> --require-panel --in-place` 做线性概率池、比分汇总和分歧度量；缺少 schema v2、多智能体字段、最终修订或概率不一致时必须阻止出卡。
9. 足球共识锁定后才揭示竞彩赔率。市场若与共识明显冲突，只能触发事实复查；没有新事实时不得为了贴盘改写概率。
10. 若 subagent 工具不可用，按相同角色顺序做隔离复核，并在 `multi_agent_analysis` 中标明 `execution_mode: sequential_fallback`，不得假装完成独立盲审。

不要强迫所有角色得出相同比分。最终必须给出可执行的共识，但高分歧时保留少数意见、降低置信度，且不得标记“稳胆”。只保存结构化结论、证据摘要和修订记录，不保存冗长原始对话。

参考 `references/prediction-framework.md` 的权重框架，对收集到的信息做结构化推理：

1. 为每队估算一个"综合实力/状态分"，列出加分项与减分项。
2. 结合 H2H 与风格克制做调整。
3. 叠加情境因素（出线需求、停赛、场地/旅行等）。
4. 先列出 4–6 个候选比分，并标注它们对应的比赛脚本：
   - 强队早进球后继续打开（如 4-0、4-1、5-1）
   - 强队久攻不下但控制局面（如 1-0、2-0）
   - 弱队先进球或偷到反击（如 2-1、3-1、1-1）
   - 红牌/点球/早球/末轮净胜球需求造成的高方差比分
5. 单独估算纪律与判罚变量：
   - 预计总黄牌数、红牌/点球概率、判罚尺度会让比赛更碎还是更流畅。
   - 若裁判未公布，不得编造姓名；用赛事平均尺度 + 两队风格估计，并明确不确定。
6. 淘汰赛阶段单独估算常规时间与晋级路径：
   - 常规时间比分和概率。
   - 加时赛概率、点球大战概率、最终晋级概率。
   - 不能把“常规时间平局”和“全场胜负”混为一谈。
7. 1/4 决赛及之后必须新增逐段比赛进程预测，并写入 JSON 的 `match_process` 字段：
   - 以时间段拆解：`0-15 分钟`、`15-45 分钟`、`45-60 分钟`、`60-75 分钟`、`75-90 分钟`，若淘汰赛有明显平局路径，还要写 `加时/点球分支`。
   - 每个时间段说明：谁会更主动、压迫/控球/防反如何变化、哪一侧对位会制造机会、何时可能出现首球、补水/半场/换人窗口如何改变走势。
   - 进程预测必须回扣波胆：解释首选比分、次选比分和 10 个以上波胆赔率中，哪些比分对应哪些比赛脚本。
   - 如果球队有伤疑、停赛或预计首发不确定，要在进程预测中写出分支，不得把预测首发当官宣。
8. 检查是否陷入模板化：
   - 不得仅凭"强弱明显"默认 3-0。
   - 不得仅凭"实力接近"默认 1-0 或 1-1。
   - 如果最终选择常见比分，必须说明为什么它比高比分/冷门脚本更合理。
9. 得出：
   - **预测比分**（小组赛为全场 90 分钟；淘汰赛默认写常规时间比分，必要时附全场晋级判断）
   - **总进球数预测**（预计进球总数，及大/小球倾向，如"预计 2-3 球，偏大 2.5"）
   - **胜平负倾向** 与 **大致概率分布**（如 主胜 50% / 平 28% / 客胜 22%）
   - **比赛进程预测**（逐时间段脚本、首球窗口、换人窗口、加时/点球分支，并回扣波胆）
   - **出牌数预测**（黄牌区间、红牌/点球风险、执法尺度判断）
   - **教练与后手判断**（临场调整、替补深度、领先/落后脚本）
   - **淘汰赛晋级判断**（若适用：常规时间、加时、点球、晋级队）
   - **置信度**（高/中/低）与**关键不确定点**

务必写出**推理依据**，而非只给结论。

## 第四步：赔率抓取与投注建议（仅限世界杯比赛）

**只使用竞彩（中国体育彩票）官方赔率**，不再抓取北单。需抓取竞彩的 **4 类玩法**，并据此分析比分、总进球与下注方向。

### 赔率来源（竞彩官方，4 个独立玩法页面）
| 玩法 | URL |
|------|-----|
| 胜平负 / 让球胜平负 | `https://www.sporttery.cn/jc/jsq/zqspf/` |
| 比分（波胆） | `https://www.sporttery.cn/jc/jsq/zqbf/` |
| 总进球数 | `https://www.sporttery.cn/jc/jsq/zqzjq/` |
| 半全场（可选） | `https://www.sporttery.cn/jc/jsq/zqbqc/` |

> ⚠️ 竞彩正确入口是 `/jc/jsq/...`（不是 `/ic/isq/...`，旧路径已失效跳错误页）。若 URL 失效，从胜平负页导航栏链接里重新解析各玩法路径。

### ⚠️ 抓取方式（重要）
这些页面都是 **JavaScript 动态渲染**的，直接 `web_fetch` 只能拿到空表头或错误页。**必须用 Playwright**：

1. `browser_navigate` 打开玩法页 → `browser_wait_for(text="世界杯")` 等渲染。
2. 用 `browser_evaluate` 读 `document.body.innerText`，按 `06-XX` 日期 + 球队名定位当天世界杯场次。
3. **胜平负页**：提取每场「不让球」胜/平/负 + 「让球胜平负」让球数与胜/平/负赔率 + 大众支持率。
4. **总进球数页**：提取每场 0/1/2/3/4/5/6/7+ 球各档赔率，找**赔率最低档**（市场预期进球数）。
5. **比分页**：每场比分块默认**折叠**，需先点击展开按钮（`span.folderTd`，文本为 `+`）再读取；取**赔率最低的几个比分**（市场最看好的波胆）。
6. 抓取失败或当天无世界杯场次，如实说明并跳过，**不要编造赔率**。

### 价值分析与下注建议（结合 4 类玩法）
1. 把第三步估算的胜平负概率换算成"合理赔率"（≈ 1 / 概率），与竞彩实际赔率对比找价值（实际 > 合理 → 有价值）。
2. **胜平负 / 让球胜平负**：给出推荐方向；当不让球赔率过低（如 < 1.3）时，评估让球盘是否更有价值。
3. **总进球数**：结合市场最低档与自己对两队攻防的判断，给出"大/小球"倾向（如大 2.5 / 小 2.5），并指出市场预期的进球档。
4. **比分（波胆）**：把自己的预测比分与市场最看好的几个比分对照，给出"预测比分 + 高赔博胆比分"建议。
5. 每个推荐标注**风险等级**（稳胆 / 博胆 / 高风险），可附单关/串关思路。
6. **每场都附风险提示**，报告开头统一声明：投注有风险，仅供参考，理性娱乐。

## 输出格式

为每场比赛输出结构化结果，并在最后生成一份汇总。**面向用户的报告产物统一为 PNG 格式**，保存到目标日期目录，并用 `declare_artifact` 声明。

PNG 输出规则：
- JSON 顶层使用 `schema_version: 2`；少量淘汰赛的每场比赛应包含 `multi_agent_analysis`，完整契约见 `references/multi-agent-deliberation.md`。
- 目录：`reports/YYYY-MM-DD/`，其中 `YYYY-MM-DD` 是目标比赛日的北京时间日期（例如明天是 2026-06-25，则输出到 `reports/2026-06-25/`）。
- 数量：每次生成先输出 1 张 `00_赛后复盘_今日校准.png`，再每场比赛 1 张 PNG；当天 6 场比赛就输出 7 张 PNG，不额外生成汇总 PNG。
- 命名：`00_赛后复盘_今日校准.png`、`01_主队_vs_客队.png`、`02_主队_vs_客队.png` 等；比赛卡按开球时间排序。
- 00 号卡内容：对前一比赛日真实赛果、比赛过程和历史预测逐场复盘；既指出预测错在哪里，也保留预测对的推理链；小组赛末轮必须重点检查积分、同分胜负关系、净胜球、进球数、红黄牌，以及第三名出线门槛。
- 比赛卡内容：只包含单场比赛卡片信息：对阵信息、预测比分、总进球预测、胜平负概率、比赛进程预测、关键分析、多智能体研判摘要、竞彩赔率与投注建议；赛后复盘/今日校准集中绘制在 00 号卡，不重复绘制到每张比赛卡片。
- 比赛卡排版：顶部标题、对阵、比分、概率、总进球和淘汰赛预测可保持横向重点展示；其后的正文统一使用**单栏**，先放整宽的「竞彩赔率 / 建议」与「投注建议」，再放「比赛进程预测」，再放「关键分析」，最后放「其他因素」「裁判/出牌」「教练/后手」等扩展内容。
- 比分/波胆赔率至少列出 10 个市场低赔比分；比赛较少时宁可让卡片稍长，也不要把赔率和投注建议挤进窄栏。
- 淘汰赛卡片：`预测比分`默认指**常规时间比分**；卡片需额外显示“淘汰赛预测 / 全场晋级”区块，说明是否可能加时、是否可能点球、最终晋级队。
- 多智能体区块：完整 `agents/challenges/revisions/consensus/agreement` 保留在 JSON；PNG 只显示 `multi_agent_analysis.display.items` 的 2–4 条裁决摘要，包括独立观点、质疑后的修订、共识和少数意见，避免卡片变成原始讨论记录。
- 扩展分析区块：若 JSON 中包含 `match_process`、`multi_agent_analysis`、`referee`、`card_prediction`、`coach_tactics`、`bench_depth`、`knockout` 等字段，PNG 卡片必须显示对应摘要，避免只在内部推理但不交付给用户；`weather` 不再作为卡片输出字段。
- 00 号复盘卡在淘汰赛阶段要按每场比赛分段复盘，并尽量抓取真实首发、替补换人、红牌/点球和关键时间线；复盘中的「实际阵容/换人」可以用 `Cunha(Endrick 58')` 这种紧凑格式，不需要每个球员名字后都重复国家简称，避免卡片过度冗余。
- 人名标注：球员/教练/裁判等人名后必须加三字母国家或队伍简称，如 `David（CAN）`、`Broos（RSA）`、`João Pinheiro（POR）`；淘汰赛卡片尤其要给替补后手和主教练标注所属队伍。
- 清晰度：PNG 使用高密度画布导出并写入 300 DPI 元数据；中文字体使用宋体，英文、数字和赔率使用 Times New Roman；中英文与数字混排必须按共同基线对齐，避免数字或英文相对中文上下错位。
- 结构化 JSON 可保留为中间数据源，但不要再把 HTML 作为报告交付格式。

每场比赛包含：

| 字段 | 说明 |
|------|------|
| 对阵 & 小组 | 主队 vs 客队，所属小组 |
| 开球时间 | 北京时间 / 当地时间 |
| 预测比分 | 最可能比分（可附次选） |
| 胜平负倾向 | 主胜/平/客胜 + 概率分布 |
| 总进球预测 | 预计进球数 / 大小球倾向 |
| 比赛进程预测 | 逐时间段推演比赛走势、首球窗口、换人窗口、加时/点球分支，并回扣波胆 |
| 主裁判与出牌 | 主裁判姓名（若已公布）、执法尺度、预计黄牌区间、红牌/点球尾部风险 |
| 教练与替补后手 | 主教练风格、临场换人、替补深度、领先/落后 Plan B |
| 淘汰赛预测 | 常规时间比分、加时/点球概率、最终晋级队（淘汰赛必填） |
| 关键分析 | 状态、H2H、风格、停赛、出线形势等要点 |
| 置信度 | 高/中/低 + 主要不确定点 |
| 竞彩赔率 | 胜平负 + 让球胜平负 + 总进球数(最低档) + 比分(最看好) |
| 投注建议 | 方向、玩法（胜平负/让球/总进球/比分）、风险等级（仅世界杯） |
| 多智能体研判 | 各角色盲审倾向、质疑与修订、概率共识、分歧等级、少数意见和触发改判条件 |

汇总部分：当天所有比赛一览表 + 综合下注建议（如"今日推荐 2 场，1 稳胆 1 博胆"）。

汇总部分还必须包含：
- **赛后复盘**：近期历史预测的命中与误差摘要。
- **今日校准**：本次预测如何根据误差避免模板化，尤其说明哪些比赛存在大比分或冷门尾部风险。

## 注意事项

- **必须真实联网**收集数据，信息不足时如实说明，不要臆造成绩/赔率/伤停。
- 赔率页面是动态的，**坚持用 Playwright**，不要因为 `web_fetch` 失败就放弃。
- **只用竞彩官方赔率**（`/jc/jsq/...`），不再使用北单；比分玩法默认折叠需点开 `span.folderTd`。
- 区分「不让球胜平负」与「让球胜平负」，避免赔率误读。
- 总进球数取赔率最低档作为市场预期；比分取赔率最低的几个作为市场最看好波胆。
- 不要让比分预测过度趋同；每场都要评估大比分、冷门、弱队进球和早球打开局面的概率。
- 用户观点必须作为待检验假设隔离；第一轮有票角色不得看到用户比分倾向、其他 agent 观点或竞彩赔率。
- 事实不参与投票；阵容、停赛、伤缺或来源冲突只能由证据核验解决。高分歧共识必须降置信度并保留少数报告。
- 完整多智能体记录保存在 JSON，PNG 只展示 2–4 条裁决摘要；不要输出原始对话或隐藏思维过程。
- 小组赛后期务必查清积分榜与出线形势，这对预测和"默契球"判断影响极大。
- 淘汰赛必须区分常规时间和最终晋级；常规时间平局不等于没有胜负判断。
- 主裁判未公布时，不得编造裁判姓名；可以写“裁判未公布，按赛事平均尺度估计”，并降低出牌判断置信度。
- 主教练和替补后手是淘汰赛重要变量；不要只看首发纸面实力。
- 本届世界杯补水时间会放大主教练临场调整权重；报告中要写出半场、补水、加时和换人窗口可能带来的战术变化。
- 每天先更新阵容台账再分析；名单里不存在、已被替换、伤缺或停赛的球员，一律不得写进首发、替补后手、点球手或战术关键点。
- 预测阵容、替补后手、点球手前必须核查球员是否伤缺、未入名单、已下场或已伤退；live 场景只能基于当前仍在场球员判断。
- 球员、教练、裁判等人名后必须带国家/队伍三字母简称；不要默认用户记得每个人属于哪支队。
- 时间一律标注北京时间与当地时间，避免混淆。
- 投注建议**仅针对世界杯**，且附风险提示。
